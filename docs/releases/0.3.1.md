# VoicePanel 0.3.1

This release shows subtitle text without waiting for the speaker label, keeps
one label per person while the diariser catches up, adds a single-voice
acceptance run, explains a caption report with `diagnose`, and fixes a
recognition prompt that was silently dropped for `verbose_json`. It also
removes the empty-phrase recovery experiment, which produced no words.

## Text before the label

The rolling diarisation window covers two minutes and answers seconds after the
phrase. Subtitles used to wait for it, so the overlay lagged the interpreter by
exactly that long. A caption is now emitted as soon as its words are known, with
the last resolved label; the window's answer arrives later as a correction for
that phrase, matched by id (`captionSpeaker`), and repaints that line only.
Meetings still wait for the label, because the transcript is written once.

## Speaker identity while the engine catches up

A window turn and a stored person's turn are matched on the session clock.
Identity is mutual: the person must explain most of a window id and the id must
carry most of what is known about that person inside the window; the ids left
over are settled by elimination. A voice the engine re-cut into two ids no
longer mints a second label, and a window that overlaps no labelled speech names
nobody. When the engine falls behind the audio, the next window continues from
the last labelled second in half-window steps, so the speech in between is heard
by a window that still overlaps what came before instead of being skipped.

## Single-voice acceptance

`singleVoiceRecordingKeepsOneLabel` replays `runtime/bench/single-voice-16k.wav`
— about 2.5 minutes of one person, looped — and fails if the recording gets more
than one label, if more than a fifth of its captions are unlabelled, or if
per-phrase latency grows. A three-voice fixture can only prove that people are
separated; only a single-speaker recording proves the rolling window does not
invent participants. Enable it with `VOICEPANEL_SUBTITLES_SINGLE_BENCH` set to
the service URL; the report is `runtime/reports/subtitles-single/result.json`.

## Diagnose a caption report

`python tools\bench\transcript_quality.py diagnose --report
runtime\reports\subtitles-long\result.json` describes each empty phrase by its
length, its loudness against the phrases that did carry words, the human voices
inside it and how close it starts to a turn change. Each lost turn is charged to
`not_cut` (no phrase covered it), `empty_phrase` (the phrases over it came back
without words) or `partial` (some words, under half). The fixture loops the same
60-second clip, so the output counts distinct offsets: one reproducible failure
is not read as twenty random ones.

## The prompt reaches every response format

A `verbose_json` request used to be routed to the detail variant, which took no
`prompt` at all. The glossary was dropped without an error, and the caller could
not tell from the answer. The detail request now carries the prompt; the service
tests check both formats.

## Empty-phrase recovery removed

The live path no longer retries a phrase that the recogniser returned no words
for. The retry was measured on the 600-second fixture: it filled 10 of the 20
empty phrases, but the text was `P` nine times and `Puh.` once. Every empty
phrase's carrier turn is 0.64–1.14 s — the phrase itself — and the decoder
returns one character or nothing: the fragment is the tail of a word whose
beginning is already in the previous caption. With a plausibility gate the run
was exactly the baseline (empty 14.6 %, lost 20.6 %, WER 0.303, order 0/0,
187 → 186 ms), while each empty phrase still cost two extra requests. The
pending "…" line and the repaint-by-id plumbing that existed only for it are
gone with it.

## Verification

| Check | Result |
|---|---|
| Panel, model-free | 103 passed, 0 failed, 8 skipped |
| Service tests | 201 passed |
| Long captions, 137 phrases | 20 empty (14.6 %), lost 20 of 97 (20.6 %), WER 0.303, CER 0.224, covered speech 88.1 %, names 92.3 %, terms 79.5 %, 187 → 186 ms, order 0/0 |
| Single voice | 27 of 27 captions, 1 label, 248 → 248 ms |

The long run is the baseline: this release does not change caption quality. It
removes a path that did not, and records why.

## Known limitations

- About one phrase in seven still returns no words, and about one turn in five is lost on the three-voice fixture.
- A caption still appears after the VAD endpoint rather than while audio arrives.
- Speaker labels are not renameable in the subtitles overlay.
- Quality figures come from an English fixture; Russian meetings are not measured.
- Merging a boundary fragment into a neighbouring caption is not implemented; it is the next experiment in the roadmap.
