# VoicePanel 0.3.0

This release names the speaker in captioned application audio, keeps one number per person for a whole call, and makes the caption acceptance run score the transcript itself. It is the first public release since 0.1.0: 0.2.0 was built and tested locally but never published here, so its changes are part of this archive and are recorded in [CHANGELOG.md](../../CHANGELOG.md) and [0.2.0 notes](0.2.0.md).

## Speaker labels in captions

Captioned application audio now runs through the same rolling diarisation window a meeting uses, so a subtitle line starts with `Speaker 1:`, `Speaker 2:` and so on. The label is attached to the line that is visible: the heard line, the translation, or the transcript-only caption.

Numbers follow people rather than windows. A diariser reports the last two minutes again on every phrase, so a person's turns are stored merged into intervals; otherwise the re-reported copies outvoted the voice that was actually speaking and a quiet third participant was absorbed into the most-recorded one. A window id inherits a person only when that person's speech covers at least half of the id's own seconds in the window, and a fragment at a turn boundary names its phrase by the closest known voice without minting a new speaker. A new session starts from a clean timeline, since the diariser numbers people per run.

## Transcript quality in acceptance

The long caption fixture now scores the final transcript against a human reference: WER, CER, covered speech, lost turns, phrases that come back without words, speaker-name accuracy and term recall. A lost turn is counted by words, not by time: captions sit wall to wall, so an overlap test reported zero lost turns on every run. A turn is lost when fewer than half of its words appear in the captions over its span, and the report also carries the share of checked words that no caption echoes.

Measured on the 600-second, three-voice English fixture with 137 phrases and 97 reference turns:

| Measure | Result |
|---|---|
| WER / CER | 0.303 / 0.224 |
| Covered speech | 0.881 |
| Lost turns | 20 of 97 (0.206) |
| Words absent from every caption | 0.244 |
| Phrases that returned no words | 20 of 137 (0.146) |
| Speaker names | 0.906 |
| Term recall | 0.795 |
| Median time to a caption | 4.7 s |

## Offline re-pass

`tools/bench/transcript_quality.py` scores a live run, compares it with an offline pass, and runs that pass on a saved recording: whole-file diarisation, re-recognition per diarised turn and per VAD phrase, cleanup with the meeting notes and the context document, and a named Markdown transcript. On the same fixture the offline pass keeps better names (0.993 by turn) but a slightly worse transcript than the live run (0.369 WER), while 12-second blocks reach 0.297 WER with one label per block (0.680 names). Neither offline mode beats the live run on words alone, which is why the next work targets empty phrases and lost short phrases rather than a second pass.

## Windows package

The archive layout, Python environment and model installation steps are unchanged from 0.2.0; the bundle contains the panel, Qt/ONNX runtime, service source, engine binaries and licenses, and no personal settings, recordings, voice profiles or model weights. Follow [the 0.2.0 package steps](0.2.0.md#windows-package) and use this archive in their place.

## Verification and known limitations

Panel checks: 100 passed, 0 failed, 7 skipped. The long caption acceptance run passes with the gates above, and the C++ and Python scorers report the same lost-turn and missing-word figures. Service tests and the release package check are run before the tag; the archive contains no models and no personal settings.

Known limitations:

- Speaker labels are not renameable in the subtitles overlay; renaming exists in the meeting window, and a renamed person is used in the saved Markdown.
- The finished, cleaned transcript is produced by the offline tool, not by a tab in the panel.
- The glossary is the Terminology section of the context document; there is no separate field in settings.
- Quality figures come from an English three-voice fixture. Russian meetings are not measured yet.
- About one phrase in seven still returns no words, and about one turn in five is lost on this fixture.
- A caption still takes about 4.7 seconds to appear; the live path recognises after the VAD endpoint rather than while audio arrives.
- Models and engines are unchanged. Whisper remains an option for machines that can run it. The NeMo streaming comparison stays experimental and is not wired into the service.
