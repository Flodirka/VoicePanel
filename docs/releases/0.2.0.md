# VoicePanel 0.2.0

This release repairs speech-engine selection and voice design, updates the native runtimes, and fixes a correction failure that left later dictated text queued until capture was restarted.

## Continuous capture

Keep the microphone on. Completed phrases are processed and inserted in order. A failed request keeps its text; the next phrase retries the queued text. The silence-reset setting archives the current document and clears its processing state without stopping capture. The service no longer sets an output-token cap from the length of the input. Explicit API client caps remain supported.

The default GEC model uses its trained single-turn prompt. Recording remains continuous while correction requests remain independent. The text model's context window is separate from the panel's silence timer. Meeting transcripts are retained throughout the meeting; a dictation rollover does not erase them.

## Windows package

The Windows archive contains the panel, Qt/ONNX DLLs, service source and engine binaries. It requires Windows x64, Python 3.12 x64 and the chosen model files. It does not contain personal settings, recordings, voice profiles or large model weights. It is not a Python installer.

The native OmniVoice CUDA executables in this local build target compute capability 8.9. Use the CPU variant or rebuild from the pinned source for older NVIDIA architectures. Audio.cpp and llama.cpp use their upstream CUDA 12.4 distributions.

Extract the archive, open PowerShell in `VoicePanel`, and prepare the Python environment:

```powershell
python -m venv runtime\venv
.\runtime\venv\Scripts\python.exe -m pip install --only-binary=:all: --require-hashes -r service\requirements.lock
```

Install the model files listed in [Models](../models.md), then choose the installed engines and start the application:

```powershell
.\runtime\venv\Scripts\python.exe tools\configure_backends.py --tts omnivoice --asr audiocpp
.\tools\start-service.ps1
.\tools\start-panel.ps1
```

For an existing installation, preserve `config.yaml`, `runtime/state`, `runtime/voice-library` and model files. The local test release uses these installed models and its prepared Python environment. Close the old panel and service before launching that separate folder.

## Verification and known limitations

Service tests cover the model prompt, output-cap behavior and package boundaries. Real models completed 25 consecutive RU/EN correction and translation requests in one service lifetime. Panel checks cover recovery without restarting, silence rollover, meeting labels and queued interpreter/subtitle requests with a failure in the middle.

Native Windows acceptance completed 92 checks with no failures. It includes microphone start/frames/stop, audio playback, hotkeys and real recognition/correction before capture ends. On the public speech fixture, the session stayed open for 37.7 seconds and delivered 12 previews, five final segments and three text batches. The docking test now uses the measured panel size; the former offscreen failure came from its hard-coded 640 px assumption for a 720 px panel.

Three target-field workflows still need manual foreground acceptance: two external-editor scenarios were not run, and Windows refused foreground activation in the test's own insertion field. The computer-use helper was unavailable. These checks are not counted as passes. Real call routing and voice similarity also require user acceptance. The NeMo streaming comparison remains experimental; NeMo is not part of the active service.
